# Compact yard: stages A and B

Implemented source milestone, not a verified Unity build or a finished game. The creator's current automation brief supersedes the earlier wire-demo scope. The attached 48 × 36m map is an example equipment layout: only the office/shop/sales, receiving area, entrance and boundaries are fixed. See COMPACT_AUTOMATION_BRIEF.md for the complete request and COMPACT_WORLD_VERIFICATION.md for original asset provenance/budgets.

## Open the new default

Use Unity 6000.3.25f1 with pinned URP 17.3.0. After pulling, let imports finish, then run **Scrapshift → Create or Open Compact Yard**. The old **Create or Open Prototype** command is an alias. This creates only missing generated resources/scenes and opens `Assets/Scrapshift/Generated/CompactScrapyard.unity`; existing scenes/balance assets remain. The compact scene becomes the first enabled build scene; `Generated/Scrapyard.unity` remains the explicit legacy continuation. Open the compact scene and press Play. The new balance is `Resources/ScrapshiftCompact/Balance.asset`; the previous `Generated/Balance.asset` still controls the legacy yard.

Opening the old scene directly still starts the old game. A pull cannot reconstruct generated scenes or prove Unity compilation here. Do not delete Generated, old saves or preferences to receive this milestone.

## Implemented scope

Stage A: a small starting balance (€8), one movable manual bench, one stationary scrap car and one refrigerator. Inspection snapshots work steps and yields; empty-hand work advances individual dismantling stages. Collect separate motor/wiring/body-metal/compressor/plastic components. Whole vehicles/appliances are never carried. Workbench recipes turn components into copper, steel and insulation. Inputs are consumed once at loading; exact yields/progress remain until every output is collected. Each successful collection creates one portable stack, with no repeat output. Dropped stacks are fixed views, not active rigidbodies.

Sales show unit price, bundle subtotal, material-level bonus, total and eligible XP before confirmation. Default copper is €3/2XP per unit; steel/plastic/insulation are €1/1XP. Only legitimate recovered-material sales earn XP. Transfers, collections, purchases, failed actions and re-selling an already-consumed item cannot earn it. Imported historical inventory has no invented eligibility/XP. Level thresholds and bonuses are editable; the default level-two bonus is 12%, giving an ordinary copper bundle €10 instead of €9. Starter scrap reaches €93; two free wire loads reach €117 and 82XP, enough for the €45 generator plus €60 Tier1. Replacement scrap costs €25/car and €15/fridge; renewable free wiring and a last-bench dismantling safeguard protect the earning loop.

Stage B: purchase/place bench, generator and Tier1 anywhere valid in the open yard. Preview supports optional 0.5m grid snap, 90° rotation, green/red validation, reserved entrance/office/receiving access, rotated equipment/large-scrap/loose-item footprints, actual static-collider overlap and player clearance. Core validation runs again at confirmation; preview/cancellation spends nothing. Empty disconnected equipment can move. Dismantling refunds half its paid purchase price, except free starter equipment; at least one manual bench remains.

Inspect a generator or scrapper to connect/disconnect another nearby physical power port (default 12m cable range). Visible amber cables terminate at model sockets. Supply/demand use the full connected graph. Default generator supplies 6 kW, Tier1 reserves 3 kW; overload pauses all connected consumers, not a subset selected by iteration order. Timed jobs retain inputs/progress/output through outage, disconnection, overload or capacity pressure. Tier1 requires manual loading and output collection; there is no automatic conveyor/intake/export in this stage. Generators have no fuel system/cost yet.

Menus/Settings/capture pause time and processing, release the cursor and consume inputs through release. Construction allows walking/look while running machines continue, with gameplay interaction/drop/work routed exclusively to preview controls. HUD, inspection, help and tutorial use saved action labels. Build catalogue defaults toB; rotate defaults toR. These append the existing seven bindings without changing their IDs, mouse action, sensitivity or invert-Y. Occupied B/R use unused fallback keys. Control/video/audio files remain separate from gameplay saves.

Data-driven limits, parts/prices/XP, recipes/yields/strokes/time, large-object stages, starting supplies, equipment costs/footprints/power/capacity/unlocks and experience curve live in the editable compact balance. Job snapshots survive later recipe/time/yield changes. Lowered purchase/stack limits preserve already-owned state against durable safety limits. Oversized input bundles are rejected atomically; splitting stacks is not implemented. Fixed scenery is regionally batched; new nine meshes total 8,232 triangles. Views refresh on transactions/readiness, HUD at 10 Hz, and power graph results are cached rather than reconstructed for every machine every frame. Existing render presets and four-source audio budget remain; actual FPS is unmeasured.

## Saves and explicit transition

`yard-v2.json` is distinct from `yard-v1.json`, both under Unity persistentDataPath. Version two saves placements/global unique IDs, carry/loose inventory, inspected large-object snapshots, processing/output snapshots, power links, XP and player state. Required root fields/types and complete model/graph state are validated before accepting data. Atomic writes retain a last-good backup. Backup recovery never silently resets a yard; subsequent writes retain the valid backup and move the unreadable primary into a unique recovery file. If primary and backup fail, Start is blocked until the user explicitly chooses an archived new yard. Archives retain primary, backup, interrupted temporary and unreadable files.

Optional title-screen import explicitly previews its limitations and requires confirmation. It copies cash and portable quantities, places accessible bundles on clear gravel, and converts wire-bench/machine progress into exact snapshots. The old powered stripper becomes a Tier1, requiring a bought generator/cable. No initial car/fridge gifts or historical XP are added. Custom old work strokes/hand tools and reserved copper yields remain. The original file/backup is never changed, and the complete original JSON is retained inside the new save. Old repairs, customer escrow, daily records and upgrades continue in the retained legacy scene; they are not presented as silently migrated. Repeated import replaces an archived compact yard rather than adding rewards to it. Current compact prices apply to imported quantities.
